# Skill: excel-template-builder

这个 Skill 提供了一套标准化的工作流，用于将人类习惯阅读的原始表格自动清洗并重构为符合数据库规范的数据格式，最终构建可复用、全自动计算的 Excel 模板。

## 目标与原则
- **数据规范化**：满足数据库严格的范式要求（清理物理格式阻碍，并进行必要的数据结构重组）。
- **逻辑透明**：通过清晰的工作表划分，保留所有数据处理的中间环节，保证逻辑链条 100% 可追溯。
- **动态延展**：建立的计算规则和公式不能锁死行数，必须支持后续任意追加数据行且结果自动更新。

---

## 工作流与子技能 (Sub-skills)

### 1. 数据清洗子skill (Data Cleaning)
专注于解决数据表格的物理格式阻碍和数据质量问题，确保后续结构化提炼的顺利进行：

*   **处理合并单元格**：数据库不支持合并单元格，每一行必须是独立的完整记录。
    *   *行动*：如发现合并单元格，必须将其拆开。
    *   *确认*：主动询问用户拆开后的空白单元格是采取“全部填入相同的值（向下填充）”还是“将数值平均分配”。
*   **统一字段名**：
    *   表头必须是唯一列名。如果不唯一，按顺序追加后缀（如 `-1`, `-2`）。
    *   绝对禁止使用空格和特殊中文字符。强烈建议并默认使用英文下划线命名法（Snake Case，例如 `user_id`）。
*   **处理空值 (NULL)**：
    *   *确认*：如果数据中存在空格，必须与用户确认这是代表真正的“无数据”（可忽略/保留NULL），还是应该填充“默认值”（如 0 或 "未知"）。
*   **格式统一**：
    *   确保日期列全部被识别并设置为标准的日期格式。
    *   确保数值列是纯数字，剔除其中混杂的单位文字或符号（如 "100元" 必须清洗为 "100"）。

### 2. 提炼数据库规格子skill (Database Spec Extraction & Restructuring)
在此阶段定义最终的数据结构（Schema）。AI 需根据原始数据表格重构标准的数据库描述，**特别是处理不符合数据库范式的多维表**：

*   **识别并处理二维交叉表 (逆透视 / Unpivoting)**：
    *   *场景识别*：识别原始数据是否为二维展示表（例如：行是“科目/财务指标”，列是“年份/月份”等动态维度）。
    *   *结构重组*：如果是二维表，必须在提炼规格时执行“宽表转长表 (Unpivot/Melt)”的扁平化结构重构。将其定义为标准的 3 列或多列关系型结构：
        1.  `维度列 (Identifier)`：保留原有行头（如 `account_subject`）。
        2.  `属性列 (Variable)`：将动态列表头合并为一列（如新建一列名为 `period` 或 `year`）。
        3.  `数值列 (Value)`：对应交叉单元格内的提取数值（如新建一列名为 `amount`）。
*   **提取字典规格**：输出最终结构清晰的字段名、字段属性。
    *   必须明确标注：文本 (Text)、数字 (Number/Decimal)、日期 (Date)、布尔值 (Boolean) 等。
    *   对于类别型字段（可选清单），必须列举具体示例（如：`status`: "已发货", "待发货"）。
*   **无数据模拟 (Mocking)**：如果用户未提供具体业务数据，AI 需基于提炼出的规格描述自行捏造合理且符合逻辑的业务示例数据（不少于 10 行），用于模板的初步运行和验算。
*   **双向验证能力**：在脱离公司原有电脑和文件的环境下，AI 能够仅凭这份“数据库规格描述文字”，100% 还原并重构出与最初始状态完全相同的源数据表格结构，并填入模拟数据。

### 3. Excel模板建立子skill (Excel Template Creation)
根据重构后的标准数据和计算逻辑规则，生成最终的自动化 Excel 数据处理模板。

*   **无限扩展性要求**：在准备模板的数据透视表范围或公式时，绝对不能限制数据行数。必须使用整列引用（如 `A:A`）或动态结构化表格，以确保后续用户随时在末尾追加任意行数的数据，整个表格能够自动计算并更新最终结果。
*   **四大区块划分**：整个 Excel 模板的工作表 (Worksheets) 必须分为四大类，并建议用户使用三种以上的标签颜色进行区分：
    1.  **逻辑说明 (第一页 / 首个 Sheet)**：由 AI 自动生成，详细写明整个表格的数据流向、数据清洗与逆透视规则、计算逻辑以及各个表的用途。
    2.  **源数据**：只存放经过清洗并完成数据库规格化重构（如逆透视后）的、符合标准长表格式的基础数据。
    3.  **处理中间过程**：保留所有为了计算最终结果而建立的辅助列、辅助公式表或数据透视表。必须保证所有数据的计算逻辑链条一目了然、可以核查追溯，绝不能只写死最终数字。
    4.  **结果和展示图表**：放置最终计算出的核心指标、汇总数据或可视化图表。
